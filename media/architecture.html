Architecture & Technical Information

softPlay, end to end.

A single reference for how this VS Code extension is built, how it caches data locally, how it talks to the GitHub Copilot LLM, and how to use every button on screen — from architect deep-dive to first-time click-through.

Offline-first No external cache server Local system memory only GitHub Copilot Chat (BYO subscription) Java + Python

Executive Summary

What softPlay is, in five sentences a software architect can act on.

  • 1softPlay is a VS Code extension that records browser flows with Playwright Codegen, or a manually-built REST request, and turns either into production-style test code using GitHub Copilot's LLM.
  • 2Two automation modes, one pipeline: UI Automation (Playwright, browser-driven) and API Automation (REST Assured / requests, no browser) share the same settings, caching, and LLM plumbing.
  • 3Nothing runs in the cloud except the LLM call itself. Browser recording, code execution, environment checks, and all caching happen as local child processes / in-process memory on the developer's machine — a deliberate fit for bank/enterprise networks with restricted egress.
  • 4The LLM is never bundled or self-hosted. softPlay borrows the user's own GitHub Copilot Chat subscription via VS Code's standard vscode.lm API — no API keys stored, no separate billing relationship.
  • 5Caching is intentionally simple: three in-memory, TTL-bound caches (no Redis, no disk database) cut down repeated process spawns and repeated LLM token-counting calls, without ever risking a stale answer for something that matters.
  • 6Every credential is encrypted by default — in both modes, with no setting to turn it off. See "Auto Password Encryption" in Components.

How ownership is wired

Composition root

extension.ts

On activation, creates one SettingsStore and one ObjectSpyPanel, registers the sidebar view + four commands (objectSpy.openPanel, .start, .stop, .openSettings), and hands both to context.subscriptions so VS Code disposes them cleanly on deactivate.

Panel owns panels

ObjectSpyPanel

The Control Panel is the orchestrator: its constructor instantiates SettingsPanel, AiCodePanel, GeneratedFeaturePanel, and FeatureFilePanel, wires their callbacks, and is the single place prompts get built and Copilot gets called.

Request Lifecycle — "Start AI Code Generation"

The exact call chain from a button click to code appearing on screen, across both automation modes.

Webview

1. User clicks "Start AI Code Generation"

Control Panel's main.js posts { type: 'startAiProcessing' } with the current Playwright code / API request, chat-box text, and checked custom instruction files.

Extension Host

2. ObjectSpyPanel.handleMessage() routes the message

Reads current SettingsStore.get() (mode, language, model), fetches linked scenario, and calls runLlmRefinement().

Extension Host

3. Prompt is assembled

buildLlmPrompt() (UI mode) or buildApiLlmPrompt() (API mode) concatenates: the bundled standard (readSeniorQeInstructions() / readApiAutomationInstructions(), file-cached), any checked custom .md files (readInstructionFiles(), workspace-file-cached), the linked Gherkin scenario, and the recorded code or API request — user's free-text instructions are appended last so they win any conflict.

CopilotClient

4. sendPrompt(modelId, prompt, onChunk, token)

Resolves the model via findModel(), wraps the prompt in a single vscode.LanguageModelChatMessage.User(...), and calls model.sendRequest().

VS Code LM API

5. vscode.lm hands off to GitHub Copilot Chat

The installed Copilot Chat extension owns authentication and the actual network call — softPlay never sees a token or API key.

Copilot Cloud

6. The model generates and streams back

Response text arrives as an async-iterable stream (response.text), fragment by fragment.

Extension Host

7. Each fragment is forwarded live

onChunk() calls postLlmChunk(), which posts to the webview so the AI Generated Code panel updates character-by-character, not after a long silent wait.

Extension Host

8. On completion

extractCodeBlock() pulls the fenced code block out of the full response; AiCodePanel.finish() renders it; recordReceivedTokens() counts the response via the (cached) countModelTokens() and updates the Token Monitoring bar.

"Generate Feature File" and "Verify & Fix Code" follow the same shape — different prompt builder, same sendPrompt()/streaming/extractCodeBlock() plumbing.

Caching Architecture

Local system memory only — no Redis, no external cache service, no data written to disk. Everything below lives in the extension host's own process memory and disappears on window reload.

TtlCache

Environment checks

environmentCheck.ts caches checkJavaEnvironment() / checkPythonEnvironment() results. Success: 5 min TTL. Failure: 15 sec TTL, so fixing a missing JDK/package and re-clicking "Verify & Fix" doesn't hit a stale error.

TtlCache

LLM token counts

copilotClient.ts caches countModelTokens() by sha1(modelId + text). Deterministic input → deterministic output, so this is a pure win: 200-entry cap, 10 min safety-net TTL.

FileCache

Instruction / prompt files

fileCache.ts caches the bundled prompts/*.md standards and any user-linked custom .md files, validated against each file's own mtime — an edit is picked up on the very next read.

The generic cache lookup flow

Caller

1. Build a cache key

A short, deterministic string — e.g. "python:ui:<resourcesRoot>:<storageDir>" for environment checks, or "<modelId>:<sha1 of prompt text>" for token counts.

TtlCache.get()

2. Look it up

Expired entries are deleted lazily on read (no background timers running). A hit returns immediately — zero process spawns, zero LLM round-trips.

Miss path

3. Compute for real

Run the actual execFile probe or the actual model.countTokens() call.

TtlCache.set()

4. Store and bound

Written with its TTL. If the cache is already at its size cap, the oldest-inserted entry is evicted first (simple FIFO, not full LRU) — memory can never grow unbounded across a long editing session.

LLM Integration Details

softPlay never talks to an LLM provider directly. It exclusively uses VS Code's built-in Language Model API, which in turn is served by whichever GitHub Copilot Chat models the user's own subscription exposes.

Discovery

vscode.lm.selectChatModels({ vendor: 'copilot' })

Called by listCopilotModels() to populate the Model dropdown in Settings, and by findModel() every time a request needs to resolve an id to a live LanguageModelChat handle. Never hardcodes a model list — whatever Copilot exposes today is what shows up.

Generation

LanguageModelChat.sendRequest(messages, options, token)

Called by sendPrompt() with a single LanguageModelChatMessage.User(prompt). Returns a response whose .text is an async-iterable stream, consumed with for await and forwarded chunk-by-chunk to the UI.

Token accounting

LanguageModelChat.countTokens(text, token)

Called by countModelTokens() (cached — see above) to power the Token Monitoring bar, using the model's own real tokenizer rather than a character-count guess, plus model.maxInputTokens for the context-window ceiling.

Failure handling

CopilotUnavailableError

Thrown when no model resolves (Copilot Chat not installed, not signed in, or no models exposed) — surfaced as a clear status message rather than a raw stack trace anywhere the AI features are triggered.

🔐 VS Code shows its own one-time consent dialog the first time any extension calls the Language Model API in a session — softPlay does not, and cannot, bypass that gate.

Data Flow & Security Boundary

What stays on the developer's machine, and the one thing that ever leaves it.

🖥️ Stays on the local machine

  • Recorded Playwright code (Codegen writes to a temp file, polled and streamed locally)
  • Every child process: Chrome/Edge, pytest, mvn, java, python
  • All three caches (environment checks, token counts, instruction files)
  • Settings (context.globalState) and saved test files
  • Environment probing (java/mvn/python version + package checks)
  • Every real password/token/API key value — Auto Password Encryption turns it into an ENC[...] token before anything is built or sent (see Components)
➜ Only the assembled prompt text (and the model's reply) crosses this line

☁️ Sent to GitHub Copilot's cloud

  • The full prompt: recorded/API code, bundled + custom instructions, linked scenario, and chat-box text
  • Any credential-shaped value in that prompt is already an encrypted ENC[...] token, never the real value
  • Governed entirely by the user's own GitHub Copilot subscription and GitHub's data-handling policy
  • Only when "Link with GitHub Copilot LLM" is switched on — off by default
⚠️ Auto Password Encryption catches credential-shaped fields automatically, but it's a heuristic, not a guarantee — avoid pasting real production data (customer PII, production passwords) into recorded flows or the API request builder as a matter of policy, non-credential fields included.

Component Reference

One row per module — its job, and what it never does.

Feature — Auto Password Encryption

Every credential, encrypted by default — UI Automation and API Automation alike

Any password typed into a recorded browser flow, or entered into any of the API Automation Authorization tab's auth types (API Key, Bearer, Basic, Digest, OAuth 1.0/2.0, Hawk, AWS Signature, NTLM, Akamai EdgeGrid), is encrypted locally the instant softPlay touches it — before it is ever included in a Copilot prompt, and before it is written into the saved AI Generated Code file. There is no setting to turn this off: it is the standard behavior for both automation modes. A matching decrypt call — plus, for Python, a small bundled pure-Python AES implementation, so no pip install is ever required — is added to the generated file automatically, so the test still actually runs.

Algorithm

AES-256-CTR + HMAC-SHA256, Encrypt-then-MAC, with independently derived cipher/MAC keys. Natively available in Node, the JDK, and (via a bundled implementation) Python — zero extra dependencies to install offline.

Key storage

One 32-byte key per install, generated once and held in VS Code's own SecretStorage — OS-keychain-backed (Windows Credential Manager / macOS Keychain / libsecret) — never a hardcoded key, never a plain file.

Token format

ENC[v1:iv:tag:ciphertext] — self-describing and base64, safe to embed directly as a Java or Python string literal with no escaping.

Runtime key delivery

SOFTPLAY_SECRET_KEY environment variable — set automatically for "Verify & Fix Code"; a real CI/CD pipeline supplies it from its own secrets manager (Vault, CyberArk, Azure Key Vault, ...) instead.

▼

Scope note: this protects NON-PRODUCTION test credentials from appearing in plaintext in an LLM prompt or a saved/committed source file — it is intentionally not a replacement for a bank's production-grade secrets infrastructure (HSM-backed KMS, per-environment key rotation, centralized audit), which is exactly what the environment-variable handoff above is designed to plug into for a real CI/CD pipeline.

Quick Troubleshooting

The handful of messages people actually run into.

"No Copilot chat models found"

Install the GitHub Copilot Chat extension and make sure you're signed in to a GitHub account with Copilot access.

Environment check failed (Java/Python)

Install the missing tool and make sure it's on your system PATH, then click Verify & Fix again — the failure is only cached for 15 seconds.

Nothing happens when I click Start

Check the "softPlay" Output channel (View → Output, then pick softPlay from the dropdown) for the exact error.

My generated code seems out of date

Click "Regenerate AI Code" — it always resends your current, live code, not an old snapshot.
